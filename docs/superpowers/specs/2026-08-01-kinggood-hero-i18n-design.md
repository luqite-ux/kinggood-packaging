# KINGGOOD 首页厂区轮播与四语网站设计规格

日期：2026-08-01  
项目：`kinggood-packaging`  
正式域名：`https://kinggoodpackaging.com`

## 1. 目标

在不破坏现有英文站视觉、Supabase 数据接入、后台代理、SEO 和正式域名的前提下，完成两项升级：

1. 首页 Hero 使用两张真实厂区照片轮播，并完整展示厂房或车间主体，不再出现厂房只显示一半的问题。
2. 网站提供英文、简体中文、德语和西班牙语四种语言，并让每种语言都具备可索引、可分享、可维护的独立页面。

## 2. Hero 轮播设计

### 2.1 图片

轮播固定使用项目已有的两张真实客户图片：

- 厂房外景：`/factory-exterior.png`
- 生产车间：`/factory-production.png`

不使用生成图片、图库图片或其他客户的工厂照片。

### 2.2 构图

每个轮播画面由两个图片层组成：

- 背景层：同一张图片铺满 Hero，轻度放大并模糊，用于填充宽屏空白。
- 主图层：原图按完整比例显示，使用 `object-contain`，确保厂房和车间主体均不被裁切。
- 遮罩层：独立深蓝半透明渐变，保证导航、标题、正文、按钮和指标符合 WCAG AA 对比度要求。

文字层不得设置整体透明度；遮罩必须使用独立、不可交互的图层。

### 2.3 动效与控制

- 自动播放间隔：6 秒。
- 切换方式：交叉淡入淡出。
- 单张图片入场：从约 `scale(1.06)` 缓慢回落至 `scale(1)`。
- 轮播底部提供当前页圆点、上一张、下一张和暂停/继续按钮。
- 鼠标悬停、键盘聚焦或页面不可见时暂停自动播放。
- 用户启用 `prefers-reduced-motion` 时取消缩放和自动播放，只保留即时手动切换。
- 所有控制提供英文可访问名称，并随当前语言切换。

### 2.4 响应式

- 桌面端：完整主体居中，保留现有 Hero 文案与指标布局。
- 平板端：主图保持完整，适当降低模糊背景亮度。
- 手机端：优先展示厂房或车间的完整纵向范围，文字区与控制区不得互相遮挡。

## 3. 四语信息架构

### 3.1 语言与路由

| 语言 | 语言代码 | 正式路由 |
|---|---|---|
| 英文 | `en` | 保留现有无前缀路由，如 `/products` |
| 简体中文 | `zh` | `/zh/...` |
| 德语 | `de` | `/de/...` |
| 西班牙语 | `es` | `/es/...` |

英文继续作为默认语言，避免现有英文链接变化。`/en/...` 不生成重复页面；如被访问，应永久跳转到对应无前缀英文路径。

### 3.2 语言选择器

- 桌面导航右侧、报价按钮左侧增加语言选择器。
- 手机菜单提供同一组语言入口。
- 标签使用 `EN / 中文 / DE / ES`，同时提供完整语言名称的辅助文本。
- 切换语言时尽量保持当前页面和 slug；没有对应页面时回到目标语言首页。
- 语言偏好写入 Cookie，仅用于后续访问提示，不强制覆盖用户主动访问的 URL。
- 首次访问不根据 IP 或浏览器语言强制跳转，避免 SEO 和用户控制问题。

## 4. 翻译范围

### 4.1 必须翻译

- 顶部导航、移动端菜单和页脚。
- 首页全部区块。
- Products、产品详情、Custom Packaging、Industries、About、News、Contact。
- 面包屑、按钮、空状态、表单字段、验证信息、成功/失败提示。
- 图片 `alt`、ARIA 标签、分页或轮播控制文案。
- 页面 metadata、Open Graph、Twitter Card、JSON-LD 中的可翻译字段。

### 4.2 产品与后台数据

- 前端展示层使用四语字典映射已确认的产品 slug，保持 Supabase 中的产品主键、slug、图片、规格和启用状态不变。
- 后台新增产品缺少某语言翻译时，使用英文名称和内容作为明确回退，不显示空白页面。
- 不为无法从客户资料证明的参数、认证或营销承诺自动编造翻译。

### 4.3 新闻

- 新闻列表 UI 和新闻详情框架翻译为四语。
- 文章正文仅在数据库存在对应语言版本时显示该语言。
- 当前数据库没有德语或西班牙语文章字段时，正文回退英文，并显示简短的“此文章当前以英文提供”提示。
- 不在页面请求期间调用实时机器翻译 API。

## 5. 技术结构

### 5.1 语言核心

新增独立语言模块，负责：

- 支持语言清单和默认语言。
- URL 语言前缀解析。
- 当前路径的语言切换 URL 生成。
- 字典类型和英文回退。
- HTML `lang`、canonical 和 `hreflang` 生成。

字典按语言拆分，避免一个超大文件。公共 UI、静态页面和产品展示翻译采用明确类型，构建时检查键缺失。

### 5.2 路由复用

- 现有英文页面保持原路由。
- 非英文页面放入统一的 `[locale]` 路由层。
- 页面主体抽成可复用的服务端页面组件，英文和带前缀路由传入不同 locale，避免复制四套 JSX。
- Supabase 查询继续位于服务端数据层，交互组件继续作为 Client Component。

### 5.3 Hero 组件

Hero 拆分为：

- 服务端内容容器：提供当前语言文案。
- 客户端轮播组件：只管理图片索引、计时器、暂停和 reduced-motion。
- 纯函数动效配置：便于单元测试。

## 6. SEO

- 英文 canonical 继续使用无前缀正式 URL。
- 中文、德语和西班牙语 canonical 使用各自语言前缀。
- 每个有对应版本的页面输出四语双向 `hreflang`，并将英文设为 `x-default`。
- Sitemap 覆盖四语静态页面和所有启用产品详情；新闻只收录实际可访问的语言路由。
- robots.txt 继续指向正式域名 Sitemap。
- 产品详情 metadata 与 `Product` JSON-LD 使用当前语言名称和描述；结构参数、图片和公司实体保持一致。
- 新闻详情使用 `NewsArticle`，并在正文回退英文时保持 canonical 指向当前语言 URL，不伪造翻译内容。

## 7. 可访问性与错误处理

- 语言选择器可键盘操作，包含当前语言状态。
- 轮播控制具有可见焦点、ARIA 标签和暂停能力。
- 图片加载失败时保留深蓝背景和完整可读文案。
- 翻译键缺失时回退英文并在开发环境记录缺失键；Production 不向用户输出错误堆栈。
- 无效语言前缀返回 404，不将任意字符串当作 locale。
- 所有深色图片区显式定义白色主文字和不低于 `white/70` 的次要文字。

## 8. 测试与验收

### 8.1 自动测试

- 语言代码验证、路径生成和英文回退。
- 四种语言字典关键键完整性。
- Hero 自动切换、手动切换、暂停和 reduced-motion。
- metadata canonical、hreflang 与 Sitemap 路径生成。
- TypeScript 和 Next.js Production Build。

### 8.2 浏览器验收

- 桌面端与手机端检查两张图片均完整显示主体。
- 验证自动轮播、手动控制、暂停和键盘操作。
- 逐页检查四语导航、Hero、产品、表单、页脚和详情页。
- 检查四语页面对比度、布局溢出和德语长单词换行。
- 在线回读 canonical、hreflang、Open Graph、JSON-LD、robots 和 Sitemap。
- 请求 Sitemap 全部 URL，确认无 4xx/5xx。
- 正式域名与 Vercel Production 均完成回归验证。

## 9. 交付边界

- 本次只修改 `kinggood-packaging` 客户站代码和该站部署，不修改 `huanqiu-admin` 的共享登录、权限或其他租户数据。
- 不改变产品 slug、租户 ID、正式域名、后台账号或现有询盘写入链路。
- 不引入付费翻译服务或运行时翻译依赖。
- 完成后提交客户仓库 `main`，等待 Vercel Production READY，并更新飞书记录中与语种或正式站交付状态相关的信息（若表格现有字段需要）。
